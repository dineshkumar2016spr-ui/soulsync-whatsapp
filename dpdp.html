Data Protection & GDPR Review — Soul Sync

Prepared for deployment readiness · 2026-11-06

1. What Soul Sync does with personal data

Soul Sync analyses WhatsApp chat exports for relationship communication patterns (tone, friction, reply drafts). When a user presses "Write drafts", chat text plus the user's name and goal are sent to an AI provider.

  • Chat text → held in the user's browser during chat selection, buffered server-side in memory while picking, and forwarded to the AI provider on demand.
  • WhatsApp session data → auth credentials live in `./data/auth-${userId}/` while a browser tab is connected; wiped on disconnect or on server restart.
  • Consents → stored as JSON files under `./data/consent-${userId}.json` with policy version timestamp.
  • AI prompts/responses → ephemeral, only while processing a request on the server.

3. Consent requirements per controller boundary

Under GDPR, consent is required before data crossing a controller boundary — especially where the controller's data is combined with the recipient's contact details. Here Soul Sync is technically the controller of chat text and AI outputs, so four explicit opt-ins are needed:

  • Terms of Service accepted by the user before any analysis runs
  • Privacy Policy readable and linked before consenting
  • Read chats consent — flagged when the user imports/analyses a chat
  • AI analysis consent — separately flagged when sending messages to Gemini/OpenAI

The frontend gate currently enforces all four boxes before any real connection proceeds, with each box tied back to a specific legal text. Good coverage so far. Watch out for:

  • Aggregate fallback — if the UI ever falls back to in-browser analysis without re-checking both boxes, ensure the fallback prompt still references the consent choices.
  • Existing data export — users who already have analysed conversations may be prompted without fresh consent if they import a new chat. Consider checking `consent-*.json` on server startup.

4. Transfer obligations under Article 44–49 GDPR

Demonstrating lawful basis and appropriate safeguards is the core checklist for deployments, not the full text:

  • Lawful basis (Art. 6) — consent covers chat analysis and AI output generation. The current four-box gate is sufficient.
  • No further transfer — Soul Sync never collects WhatsApp user IDs, contact lists, phone numbers, or other data that could enable transfers to third parties under Art. 44.
  • Recipient safeguards — obligations lie with Google/OpenAI, not Soul Sync, but Soul Sync should:
    • Enforce rate limiting on `/api/analyze` (already present: 30 req / minute)
    • Strip larger identifiers than what the user supplied (`me`, `goal` capped at 60 chars)
    • Document in the Privacy Policy exactly what is sent where
  • DPDPR if launching in the EU — requires a privacy notice, an access mechanism, and a deletion tool. Soul Sync already has a one-click "Disconnect and delete my data" flow which satisfies the deletion requirement at the application layer.

5. Data protection impact assessment

This is effectively an Art. 35 DPIA trigger — analysing personal communications via AI is high-risk processing. Recommended follow-ups:

  • Document the DPIA before first EU launch (or before any meaningful volume). Include:
    - What personal data is processed
    - Why AI analysis is necessary
    - Risk mitigation (rate limit, message cap, API key restrictions)
    - Assessment of automated decision-making
  • Note: currently no automatic "decision" is generated from analysis; the risk is low but worth documenting before scaling.

6. Access and logging controls

  • Access tokens are sha256-hashed in memory only; removed on TTL expiry or user logout. Good baseline.
  • WhatsApp auth files are wiped on disconnect and on restart.
  • Watch out: server logs may capture partial HTTP headers or WS payloads depending on transports. Ensure `log.level = 'warn'` is enforced everywhere and reject `err` logs from console if persisting anywhere.

7. Recommendations before going live

  1. Link Terms and Privacy pages in the connect gate (done) — verify they render with the right policy version text.
  2. Confirm all four AI model defaults (`gemini-2.0-flash`, `gpt-4o-mini`) are still valid; update if newer flagships exist in your dashboards.
  3. Encrypt the persistent volume at `DATA_DIR` before production deploy.
  4. Set `ALLOWED_ORIGIN` to the exact Netlify URL and reject everything else with 4403.
  5. Record the DPIA before meaningful scale or first EU launch.
  6. Add a short cookie/session notice banner acknowledging local storage usage of chat selection memory.
